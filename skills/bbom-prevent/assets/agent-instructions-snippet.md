## Architecture guardrails (bbom-prevent)

This project keeps its structure under a ratchet (`.bbom/`). Use the `bbom-prevent` skill proactively, without waiting to be asked: read `.bbom/rules.json` and `docs/ARCHITECTURE.md` at the start of a task, and say in two or three sentences what you found before each structural change. Before any structural change (new file, module, abstraction, dependency, import across modules, or editing a file over the size ceiling), search for existing code that already does the job, decide which module owns it, and follow the dependency direction in `docs/ARCHITECTURE.md`. After changing code, run `python3 tools/bbom_check.py check .` and fix what it reports. Do not edit `.bbom/baseline.json` or loosen `.bbom/rules.json` to make it pass; if a regression is truly deliberate, use `accept --reason "..."` and, for decisions, add an ADR in `docs/adr/`. Update `docs/ARCHITECTURE.md` in the same change when you alter a module, boundary or contract.
